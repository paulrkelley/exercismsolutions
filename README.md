# Exercism Solutions

This repository contains my solution code for programming exercises completed through [Exercism](https://exercism.org/).

I use Exercism to strengthen the programming and configuration skills that support my development in Linux administration, networking, infrastructure automation, cloud computing, and DevOps.

The repository currently includes solutions written in:

* Bash
* Go
* Python
* YAML

## Purpose

The purpose of this repository is to document my progress as I develop stronger programming, scripting, automation, and problem-solving skills.

These exercises give me opportunities to practice:

* Breaking problems into smaller, manageable steps
* Writing readable and maintainable code
* Debugging incorrect behavior
* Responding to failed automated tests
* Learning language-specific syntax and conventions
* Refactoring working solutions
* Using built-in functions and standard libraries
* Handling edge cases
* Developing more efficient approaches to programming problems

Although these exercises are smaller than full production projects, they help build the programming foundation needed for infrastructure automation, systems administration, CI/CD pipelines, configuration management, and cloud operations.

## Testing

Exercism exercises are normally evaluated using automated test suites provided through the Exercism platform or downloaded with the exercise.

I use those tests during development to:

1. Confirm that a solution meets the exercise requirements.
2. Identify incorrect assumptions.
3. Find missing edge cases.
4. Debug failed solutions.
5. Refactor code without changing its expected behavior.
6. Improve my understanding of the language.

The test suites themselves are not stored in this repository.

Because this repository contains only my solution files, some solutions may not run independently without the original exercise environment, supporting files, or tests provided by Exercism.

## Learning Approach

My goal is not only to produce code that passes the required tests. I also try to understand:

* Why the solution works
* Why an earlier approach failed
* Whether the code is easy to read
* Whether built-in language features could simplify it
* Whether the solution accounts for edge cases
* How the code could be maintained or extended
* How the underlying concept applies to automation or infrastructure work

Some solutions may show my progression over time. Earlier solutions may use more explicit or procedural approaches, while later solutions may be more concise or idiomatic.

This progression is intentional and reflects my learning process.
